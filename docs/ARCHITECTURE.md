# المعمارية التقنية

## التدفق
1. `app.py` يستقبل `POST /api/chat`، ينشئ قضية إن لم يُمرَّر `conversation_id`، ويحفظ سؤال المستخدم.
2. `LegalPipeline.process(question)` (في `pipeline/orchestrator.py`) يُستدعى عبر `asyncio.run`.
3. **A** — `agents.analyze` يُنتج التحليل الجنائي بخمسة عناوين ثابتة.
4. **B1** — `agents.generate_all` يطلق ثلاث فرضيات بالتوازي (`asyncio.gather`)، كل منها يرى السؤال والتحليل فقط، لا الفرضيات الأخرى.
5. **B2** — `agents.verify` يقيّم كل فرضية بالتوازي بوضع JSON، وتُقص الدرجة إلى [0, 1]. أي رد غير قابل للتحليل يُعامل كرفض بدرجة 0 بدل إسقاط الطلب.
6. **D** — `agents.synthesize` يتسلم الفرضيات المقبولة (≥ العتبة). إن لم تُقبل أي فرضية، يتسلم الأعلى درجة مع تعليمة داخلية بالتصريح بعدم اليقين، ويُسجَّل `verified_hypotheses_count = 0`.
7. يُحفظ الرد مع كامل المراحل في `messages.metadata` (JSON).

## عدد الاستدعاءات لكل سؤال
1 (A) + 3 (B1) + 3 (B2) + 1 (D) = **8 استدعاءات**، على أربع دفعات متتالية (A ← B1 ← B2 ← D). زمن الاستجابة ≈ مجموع أبطأ استدعاء في كل دفعة.

## قاعدة البيانات
| الجدول | الأعمدة |
|---|---|
| `conversations` | `id`, `title` (أول 50 حرفاً من السؤال), `created_at` |
| `messages` | `id`, `conversation_id`, `role` (`user`/`assistant`), `content`, `metadata` (JSON المراحل), `created_at` |

## نقاط التمديد
- **تبديل المزود:** `OPENAI_BASE_URL` + أسماء النماذج في `.env`.
- **إضافة مسار رابع:** أضف مفتاحاً في `HYPOTHESIS_TRACKS` داخل `agents/prompts.py`؛ المنسّق والواجهة يتكيفان تلقائياً.
- **الاختبار:** كل الاستدعاءات تمر عبر `agents.base.complete`، فاستبدالها كافٍ لعزل النماذج.

## قيود معروفة
- كل طلب HTTP ينتظر المراحل كاملة (قد يتجاوز دقيقة).
- الأسئلة المتتابعة في القضية نفسها لا تمرر السياق السابق للوكلاء.
- لا توجد مصادقة؛ التطبيق مخصص للتشغيل المحلي.
